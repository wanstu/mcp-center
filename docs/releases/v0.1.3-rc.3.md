# MCP Center v0.1.3-rc.3 — HTTPS OAuth 发现修复与关于页面

## 线上问题确认

2026-10-10 通过公开域名 `https://cmcps.wanstu.cn` 请求：

- `GET /.well-known/oauth-authorization-server` 返回 200，但 issuer 和注册、授权、Token URL 都被错误生成为 `http://cmcps.wanstu.cn`。
- `GET /.well-known/oauth-protected-resource/mcp/chenyang-windows` 返回 200，但资源 URL 也是 HTTP。
- `POST /oauth/register` 请求缺少重定向地址时返回 `400 invalid_client_metadata`，说明动态客户端注册 API 已存在。
- `GET /api/version` 证实线上运行的是 `v0.1.3-rc.2`。

**根因**：HTTPS 在 OpenResty 等反向代理处终止，传给 MCP Center 的后端请求是 HTTP；未显式指定 canonical URL 时，OAuth 元数据只能检测到后端 HTTP。不能信任来自任何请求的 `X-Forwarded-Proto` 来自动修正，否则可能遭受伪造 Header 注入。

## 新功能

1. 「设置 → 运行配置」增加 **公开 HTTPS 基础地址**，支持手动输入或从当前 HTTPS 页面一键填入，例如 `https://cmcps.wanstu.cn`。
2. 管理员保存后持久化在 `settings.json`，**立即生效，无需重启**；只接受 HTTPS 根地址，不能有路径、查询参数或用户凭据。
3. OAuth 的 `issuer`、`authorization_endpoint`、`token_endpoint`、`registration_endpoint`、受保护资源 `resource` 和 `authorization_servers` 统一使用该地址。
4. 通过 `--base-url` 显式配置时命令行优先，Web 上显示禁用，避免配置不一致。
5. 外部 HTTPS 访问但系统发出 HTTP 连接地址时，设置页明确提示不一致风险。
6. 左侧「系统」增加独立的 **关于** 页面，展示版本、Commit、公开地址、监听地址、数据目录、地址来源、开源许可证，以及 GitHub 项目链接；可复制不含密钥的诊断信息。

## Debian 安装与实际验证

```bash
sudo apt install ./mcp-center-v0.1.3-rc.3-linux-amd64.deb
mcp-center --version
mcp-center status
mcp-center doctor
```

在浏览器打开 `https://cmcps.wanstu.cn`，进入 **设置 → 运行配置**：

- 点击「填入当前 HTTPS 地址」；
- 检查字段是 `https://cmcps.wanstu.cn`（**不要包含 /mcp/chenyang-windows**）；
- 点击「保存公开地址」，提示立即生效。

然后访问：

```text
https://cmcps.wanstu.cn/.well-known/oauth-authorization-server
https://cmcps.wanstu.cn/.well-known/oauth-protected-resource/mcp/chenyang-windows
```

应分别看到 `issuer` 和 `resource` 使用 `https://cmcps.wanstu.cn`。随后在 ChatGPT 中删除失败的连接配置、重新添加原 MCP URL 验证 OAuth 注册流程。

**安全与边界**：仅管理员可以修改公开基础地址，公开 OAuth 元数据保持匿名可读。此修复不修改 Core、ADM、Kit，也不会覆盖 GitHub 上已有的正式版 `v0.1.2`。真实 ChatGPT 授权完成仍需服务器部署后进行端到端验证。
